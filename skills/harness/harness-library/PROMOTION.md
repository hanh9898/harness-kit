# Shared promotion

Deliver justified maintained shared material or a candid proposal. Use the library entry's retrieval, original-method selection and save/reconciliation steps. Promotion changes reusable material; consumer adoption remains a separate setup/evolve request.

## 1. Choose the contribution

Inspect the source revision, relevant shared material and known uses within the grant. Distinguish an inaccessible source or truncated search from evidence that no overlap exists. Record search coverage and unresolved comparisons.

Compare these alternatives against the actual contribution, intended uses and maintenance cost:

- **Reuse/reference:** point to adequate existing material. Explain whether its availability, scope and integration detail meet the need without maintaining another copy.
- **Extension:** add the uncovered contribution to an existing resource. Identify what remains shared and what the extension's maintainer must support.
- **Local retention:** keep project-specific or weakly reusable material local. Explain which conditions make wider maintenance unjustified.
- **New shared material:** create a distinct resource only when the contribution and reuse justify a separate identity, discovery route and maintenance burden.

Keep this comparison proportional; one concise decision can cover the alternatives. Select the result with concrete reuse and maintenance value. Useful unexecuted guidance can qualify as shared guidance with honest limits. Absence of broad runtime evidence alone does not require local retention.

## 2. Establish authority and responsibility

Resolve the destination's actual change procedure, applicable review and shared-write grant from existing instructions and authoritative records. A personal-save grant, writable directory, resource owner label or authority string does not grant shared changes. Reuse a sufficient one-call grant; it can authorize lasting material without authorizing later calls. Library-edit permission does not revise a separately governed harness core.

Identify a person or existing responsible role that has accepted maintenance of this contribution. Preserve the acceptance reference and responsibility for source drift, applicability and reported defects. Being named in old material is not acceptance of new duties. Use the existing procedure and selected review requirements; create no board or blanket approval lifecycle.

If authority or acceptance is missing, retain a proposal in an authorized location. State the missing condition, proposed destination and contribution, evidence limits and next action. Keep the shared target unchanged. If no proposal-save grant exists, return the proposal as a handoff and state that it was not durably saved. Independent retrieval and comparison can still finish.

## 3. Prepare the shared form

Retain source identity, revision and certainty, useful integration conditions, dependencies, customization relationships, prerequisites and limits on observed evidence. Separate source-reported results from checks performed in this run. Preserve platform-specific knowledge when it makes the contribution useful; generalize incidental examples rather than erase necessary scope.

Remove private names, customer identifiers, credentials, internal endpoints and incidental machine paths from the shared content **and its shared records**. Review content, examples, source excerpts and links for disclosure. Use an audience-safe source identity/revision or digest and an authorized restricted provenance reference when the original cannot be shared. State access limits; a digest alone does not make a source accessible. Leave the original intact. Never copy a private original snapshot into a shared history merely to populate provenance fields. If useful provenance cannot be retained safely, keep the affected promotion as a proposal and state the missing safe reference.

Load original writing-for-agents for agent-read material, and other original methods only when their work is needed, as required by the entry. Use applicable kit evidence and instruction rules in construction and review. Finish preparation with a useful resource, attributable decision and candid conditions, rather than an unsupported readiness claim.

## 4. Save, verify and continue

Prefer the destination's adequate native facilities: an existing Git-managed guidance file, document store or library operation. Keep its conventions. A maintained resource and a proposal need no new status engine or schema. For the local library fallback, a shared repository is a `project:<absolute repository path>` scope, not an invented shared permission. Save a separately identified derivative when ownership or origin changes; obey the exact-snapshot contract only for material authorized for that audience. Use safe references in a native record when that contract cannot represent private provenance safely.

Before a consequential effect, make the selected choice, alternatives, authority, acceptance and relevant review recoverable under the selected logging standard. Reuse adequate existing records. Serialize writes to ordinary Markdown with the existing single integration writer, or use the store's demonstrated conflict-safe operation. Workspace isolation and a prior read alone do not prevent lost updates. If safe integration is unavailable, retain the prepared proposal and the exact integration blocker.

Read back the result and its history/decision record. Inspect actual changed scope and known applied consumers; report coverage rather than a global unchanged claim. Retain evidence and continuation with the material: what was saved, what remains unverified, who maintains it and the next trigger. Commit or synchronize under the actual grant and destination policy; a local uncommitted file is not proof of survival after runner disposal.

On conflict, reconcile live material and preserve intervening changes. On interruption or uncertain output, inspect the destination and record before retrying. Retain a completed effect and finish only the missing evidence/record; do not duplicate the resource or reapply it. If required persistence fails, block its dependent effect unless an authorized qualified alternative preserves the same decision and continuation.

Finish with the maintained result, reference-only/local-retention decision or proposal, its durable identity, authority/maintenance basis, evidence limits, known consumer impact and next action. Promotion alone claims neither consumer adoption nor improved outcomes.
