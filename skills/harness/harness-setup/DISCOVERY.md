# Revisit capabilities when useful

Use this guide to expose the offer during onboarding or answer later discovery
questions through `harness-evolve`. Link it from the selected foundation and give
only a few examples relevant now. These are outcomes, not twelve required setup
steps or separate installations. Advice remains read-only unless saving is granted.

| Capability outcome | Example request | Selection and readiness limit |
| --- | --- | --- |
| Resource library: attributable reusable material or a saved customization | “Find reporting guidance”; “Save this as a reusable draft.” | `harness-library` owns retrieval/save/update; origin, storage authority and consumption limits matter. Applying it here remains setup/evolve work. |
| Knowledge/context: relevant sources reachable during the task | “Help agents find the release policy when drafting.” | Use evolve's [context route](../harness-evolve/CONTEXT.md) to select applicable material and check representative access/use, with freshness and privacy limits. No onboarding or library edit is required. |
| Instruction/response design: reconciled guidance and checked output | “Make reports preserve sources and mark missing facts.” | Original writing-for-agents, effective precedence and actual output/content criteria; unresolved conflicts block dependent use. |
| Standards: applicable criteria and suitable checks | “Which checks fit these recurring documents?” | Use [standards selection](../../../kit/standards/SELECT.md) for applicable requirements, conflicts and machine/human checks. Selecting a standard is distinct from satisfying it. Separate editorial checks from accuracy review of inaccessible human-only facts. |
| Authority/human involvement: usable action ceilings and review | “Which choices can the agent make, and when does it ask?” | Actual grants and prior governance still control; design, delegated-choice review and outcome-based calibration require their selected methods/evidence. Legacy scales are not automatic new defaults. |
| Team: usable responsibilities and handoffs | “Clarify who prepares and reviews a release packet.” | Inspect current team guidance and reviewer authority/context/independence. A manual or single-agent arrangement can suffice; role files do not prove execution. |
| Workflow: usable task contracts and transitions | “Make the report handoff resumable.” | Inspect current workflow guidance and existing task definitions. Preserve start, execution, completion, continuation and applicable controls; automate only when selected and authorized. |
| Tools/integrations: a usable operation route with meaningful effects | “Connect the report source and verify one read.” | Access, input/output/effect/failure contracts and actual invocation matter; configuration alone is insufficient. |
| Observation: correlated operating facts with coverage | “What is running or stalled, and how fresh is that status?” | Use current observation support and accessible sources; identity/time, stale conflicts and unknown usage remain explicit. No telemetry installation follows from a status question. |
| Outcome assessment: criterion-level findings and uncertainty | “Does this output meet our criteria?” | Use current assessment support with actual evidence, not a fabricated score or automatic adoption. Improvement needs an appropriate comparison. |
| Operations/recovery: bounded restoration and ordered continuation | “Resume after that uncertain write without duplicating it.” | Inspect live effects, preserve valid work, bound retries and report precise repair/compensation limits. Existing platforms supply execution and enforcement. |
| [Factory](../../../kit/FACTORY.md): an integrated optional unattended arrangement | “Assess whether this repeatable work is ready to run unattended.” | Select only on request. Requires actual task source, triggers, claims, stop bounds, handoffs, recovery, ownership and grants. A design can be useful while deployment remains blocked. |

All outcomes retain the consuming target's prerequisites and independent usefulness.
For advice or later improvement use the public [evolve entry](../harness-evolve/SKILL.md),
which selects current methods and relevant kit detail at that time. For reusable
material use [library](../harness-library/SKILL.md). Inspect current capability
references reached through those entries before promising implementation. This
map preserves later capability integrations without copying their method bodies.

Examples after onboarding: “Give advice only on which capability could help our
missing-source reports”; “Improve the reporting guidance using this failed
example”; “Resume onboarding for the still-unverified second host.” Record what
was selected, deferred or blocked only to the extent useful for continuation; do
not interview the user about every row or infer blanket grants from interest.
