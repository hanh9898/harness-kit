# Setup qualification at the real request-to-result seam

Use actual host requests, loading observations, results, changed/unchanged targets,
records and continuation. Structural and retrieval checks supplement this seam.
Record host/version, model, kit/provider revision, effective configuration/grants,
source identity and use. A declared skill name or installed file is not invocation.

| Situation | Inspect through the real host |
| --- | --- |
| Explicit onboarding and clear natural intent | Actual setup selection/loading and useful foundation/demo; adjacent ordinary work stays on its own route. |
| Adequate foundation and no control plane | Reuse valid guidance and records, fill only genuine gaps, produce actual initial use without redundant interviews or infrastructure. |
| Six layouts in ENVIRONMENT.md | Discover semantic roles, invoking versus consuming hosts and concrete grants. Inspect selected effects and unchanged sibling repositories/packages/personal material. Each consuming target retains its own evidence. |
| Mismatched target readiness | Installed/configured/active/intended remain distinct. A working invoking host cannot qualify an unexecuted intended host or fresh session. |
| Minimum and revisitable discovery | Every FOUNDATION.md outcome has actual evidence or a precise blocker; all twelve DISCOVERY.md outcomes are reachable without a mandatory tour. |
| Mixed onboarding and reusable save | Setup retains whole-request ownership, composes library with real storage authority, retains provenance and does not silently adopt the save elsewhere. |
| Original methods and standards | Actual selected source loading and applicable execution, including N06/E07/E08 before dependent edits and original writing guidance. Shared composition/writeback contracts remain intact. |
| Activation, provider update and missing grants | Only granted settings change, unrelated values survive, and affected invocation is actually rechecked. Missing source/policy/access blocks dependent work and supplies an exact continuation. |
| Records and interruption | Required capture/readback precedes effects; serialization and prior history survive. Inspect uncertain effects before retry; completed reconciliation avoids duplicated effects/history. |
| Discovery advice before/after setup | Narrow advice result, no unrequested adoption or records; examples lead to current supported capability references. |
| Honest support | Checks and evidence discriminate installation, eligibility, invocation, application and improvement. Broader intended hosts and inaccessible sources remain explicitly unverified. |

Repeat affected cases after material changes; preserve failed runs and original
conditions. A failed observer should be repaired against real evidence, not hidden
as a product failure. Assess semantic outcomes, not exact prose or file layout.

For persistence failures and uncertain effects, use the shared
[persistence guidance](../../../kit/PERSISTENCE.md). A blocked onboarding branch
must preserve independent work and settled questions without creating an ungranted
alternate or lock. Inspect the actual required destination and durability.

For any newly authorized assessment, choose the affected cases, acceptance criteria,
effort limit and stopping condition before running the host. Store run-specific
traces, snapshots and review records outside this source tree. Local source tests
remain separate from evidence of actual host behavior.
