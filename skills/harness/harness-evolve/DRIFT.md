# Reconcile drift and unfinished work

Read this when relevant records disagree with live targets or a request resumes unfinished work. Find the authoritative record through existing project guidance or the selected native store; preserve valid legacy entries, personal material and unknown provenance.

When failures span tasks, artifacts or shared prerequisites, use [coordinated recovery](../../../kit/RECOVERY.md) to order continuation and distinguish restoration scope from remaining blockers.

1. Recover the objective, scope, prior grants, selected references, completed work, open issues and next action. Read linked choice history when it affects the next action.
2. Inspect live files/configuration and recorded effect receipts relevant to this request. Distinguish recorded selection from applied state and observed result. A selected or accepted item may never have been applied.
3. Compare claims with observed state. Prefer current authoritative facts; an old timestamp signals uncertainty, not a universal expiry threshold. Rerun relevant safe checks within existing grants. Treat effectful checks as actions requiring their own applicable authority.
4. Resolve a discrepancy using settled intent and existing authority. If intent or authority is materially ambiguous, state the competing facts and ask only the question needed to choose. Leave unaffected work intact.
5. For uncertain writes or operations, inspect the target and history before retry. Reuse a completed effect; finish missing evidence or records. If the outcome cannot be determined, block a potentially duplicate effect and name the observation needed.

**Done:** relevant current claims reflect inspected state, valid completed work remains, and the next dependent action is either safe under the grant or precisely blocked. A resumed change does not need a new interview, onboarding, or a new copy of its history. A completed no-op resume makes no duplicate record or effect.
