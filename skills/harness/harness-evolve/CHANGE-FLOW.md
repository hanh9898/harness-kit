## Kit selection before dependent action

Select by the work you will actually perform, including supporting edits and
operations. Calling a task "already set up", "maintenance" or "babysitting" does
not remove prerequisites for its new effects. Use the owning entry's kit CLI:
inspect relevant summaries, then `kit show <id>` for the determining sources.
Reuse complete source reads already available in this context when their identity
and applicability are unchanged; a summary or remembered ID is not that read.

| Proposed work | Read before the dependent recommendation or action |
| --- | --- |
| Construct or review agent-read guidance, including a small pointer | `N06` and current original writing-for-agents; its skill-mechanics reference for a skill |
| Change current state or choice history | `E07`, `E08` and [UPDATE.md](UPDATE.md); record edits also follow the applicable writing discipline |
| Create or change unattended work or a background schedule | `J05`, `D22` and the applicable [flow controls](../../../kit/team-workflow/FLOW.md) |
| Read changing sources incrementally on a schedule | `J06`; decide how existing source state and read failures are handled |
| Report background completion or a need for human attention | `J07`; establish the available delivery route and its limits |

These triggers cover supporting effects as well as the main deliverable; use
other relevant kit groups for the requested capability. A required unreadable
source blocks its dependent work. A suggested mechanism is not mandatory tooling
or an effect grant: retain the source's applicability and certainty, and use an
adequate existing facility where it meets the requirement.

Keep a concise selection trace in the conversation for advice, or reuse the
required pre-action record for effects: kit IDs actually read, the choice or
constraint each supplied, and how the proposed result will be checked. Report
uncovered needs and material departures with their reasons. Inventory only the
proposed work; do not justify every unused catalog group or create a new log
schema. Inspect source-read evidence and actual use rather than treating a written
ID as proof. Group actions with the same sources and criteria into one decision
trace rather than logging every tool call. On continuation, revisit only changed
work or evidence.

**Done:** each distinct harness change has applicable sources and methods loaded and a
traceable choice/check, or an explicit dependent blocker. State this selection
before effects; local guidance and an adequate legacy foundation complement it.

## Original methods

Browse available original descriptions and kit summaries, then load the selected sources through the host's supported mechanism. Use native invocation when available. In hosts that support skills by reading their source, read the original SKILL.md and applicable references. Native delivery of the complete skill source is also loading; a file listing or echoed method name is not. Loading is evidence of access, not proof that the method's interaction and completion requirements were performed.

| Work | Applicable discipline |
| --- | --- |
| Clear small correction | Direct implementation and focused verification; reuse settled reasoning |
| Agent-read guidance, including this kit | Current original writing-for-agents; read its skill-mechanics reference for a skill |
| Code construction or repair | Applicable original construction/testing method and code review; agree meaningful testing seams |
| Module interface uncertainty | Original codebase-design; prototype only when useful |
| Broken or recurring behavior | Original diagnosing-bugs with representative evidence |
| Missing source facts | Original research with attributable evidence |
| Actual domain terms or architectural choices | Original domain-modeling and its artifact/writeback criteria |
| Larger specified work | Appropriate specification, ticket and implementation methods with the actual tracker |
| Unsettled design, including a short interview | Applicable original interview/design method; longer work may need a multi-session design method; use kit knowledge before questioning |
| Requested retrospective | Original retrospective method; recommendations stay distinct from adoption |
| Reusable resource authoring | Library composition with origin, ownership, source and consumption limits |

These are applicability branches, not a universal pipeline. Mixed artifacts can need different disciplines in the same request. Preserve complete inputs, interaction, outputs, handoffs and completion requirements of each selected method. An existing seam confirmation is still a confirmation. Reconcile an unfinished method from its actual state; retain valid completed work instead of replaying its ceremony. For interview completion or a resumed accepted design, use [DESIGN-WRITEBACK.md](DESIGN-WRITEBACK.md) to reconcile actual domain artifacts. For learning-only retrospectives, use [RETROSPECTIVE.md](RETROSPECTIVE.md).

## Providers and authority

Matt's original methods are recommended. For agent-read authoring, current original writing-for-agents is the selected prerequisite unless a declared replacement has applicable writing criteria and evidence of compatibility. Kit N06 complements it; N06 is not a substitute for the method.

Before dependent work, establish that the selected method can actually load and run under the host's invocation policy, including its applicable references and required nested methods. Respect explicit-only settings: invoking the outer workflow does not invoke an explicit-only child method. Source access cannot override an invocation restriction. An unavailable provider, unreadable required source or restricted invocation blocks that part; report completed work, the exact missing source/invocation/grant and the action that will resume it. Read-only inspection and independent authorized work can continue. Manual reproduction is not a fallback for a required method.

A declared alternative must preserve the consuming contract. Before using it, compare the original's applicable inputs, interaction, outputs, prerequisites, standards and completion criteria with the replacement's actual source and evidence. Explain each material match and gap, the qualified target/use, and remaining limits. A declaration or similar name alone is insufficient. A versioned mirror can establish source identity with checked digests, but still needs permitted loading and observed use on the target; different methods need substantive compatibility evidence. Keep the original condition and replacement basis in the authorized record, or in the learning/advice result when no save was granted. Block uncovered dependent work.

Selection alone does not grant installation or invocation-policy edits. Reuse sufficient host-specific grants; otherwise stop only the ungranted change. Preserve unrelated settings and verify affected invocation after an authorized change or provider update.

## Standards and handoffs

Carry applicable project knowledge, language/content criteria, grants, selected source references, relevant live state, evidence and continuation into each method. Use substantive kit material in suggestions, construction and review, including when changing this kit. N06 informs single-source guidance and pointers; E07 informs current state; E08 informs consequential-choice history. Their applicability and certainty still matter; selecting a resource does not require building its suggested tool.

The [STE-inspired writing scope](../../../kit/instruction-response/WRITING.md) complements writing-for-agents: strict structure for English agent instructions and handoffs, flavored guidance for human documentation, and structural habits for Vietnamese conversation. Read it when constructing or reviewing these artifacts. Preserve the consumer's language/content criteria. This is not formal certification or adoption of a source dictionary or linter.

The owning setup/evolve workflow remains responsible for the whole requested result after individual methods finish. Check the actual contributions against the result: suggestions used relevant knowledge before proposing a choice; construction applied it; review assessed the applicable criteria against actual artifacts. Attribute only material contributions, with outcome first and a Resource / What it changed / Evidence trace when requested. Include exceptions only when populated. Never infer application, improvement or another host's readiness from local method completion.
