# Bounded cost, latency and learning

Use this branch for a cost/time diagnosis or a deliberately selected experiment.
Keep the requested learning objective distinct from adopting its candidate.
An operating-status question uses [OBSERVE.md](OBSERVE.md); interpreting an
existing comparison uses [ASSESS.md](ASSESS.md) without new trials by default.

## Establish a useful comparison

Identify the consuming task, representative inputs, symptom or learning question,
selected quality constraints and permitted effects. Use [CONTEXT.md](CONTEXT.md)
to reach determining sources and [OBSERVE.md](OBSERVE.md) to correlate actual
attempts, usage and coverage. Inspect artifacts and commands, not only summaries.
Record source revisions, host/model/provider, settings, workload, caches, retries
and observation times where they affect comparison. Supplied sample facts remain
supplied facts; a command run now establishes only its actual observed result.

For unclear broken behavior, select original diagnosis through
[CHANGE-FLOW.md](CHANGE-FLOW.md). Establish its red-capable feedback loop before
cause hypotheses or repair; preserve its interaction and completion requirements.
Missing source facts may need original research. Required unavailable methods or
access block dependent work, with the exact prerequisite and permitted next step.
A settled comparison does not need an invented diagnosis or interview.

Retrieve `H09` for attributable usage, `H15` for evidence meaning and `H02` for
quality/regression checks. For deliberately measured optimization, read `I06`:
its inferred noise/held-out guidance applies when comparing scored candidates.
Use available observations to justify variability checks and case separation for
the actual claim. These resources prescribe neither a new evaluation platform
nor a launcher cap for every request.

Gather a suitable baseline before claiming improvement. Compare the same task
and selected criteria with a concrete candidate under comparable conditions;
explain mismatches and confounders. A current-only result can establish current
quality, with improvement unresolved. Keep elapsed wall time, active work time,
tool/process CPU time and model-serving time distinct. Overlapping work cannot
be summed into elapsed time; an end-to-end delay alone does not locate its cause.
Keep token/input volume, estimated price and attributable actual billed cost
separate. Missing, stale or misattributed usage is unknown for the dependent
claim, not zero. A rate-based estimate names its rate, date, units and coverage.

**Done:** the available evidence supports the comparison's scope, or identifies
the exact missing baseline, join, timing boundary, source or quality check. Return
useful partial findings when missing data prevents a cost or time conclusion.

## Select and execute one bounded change

State a falsifiable prediction and choose one change. Compare adequate existing
facilities with custom construction by fit, adoption, context, integration,
verification and maintenance effort. A deliberate experiment needs no invented
reuse gap. Preserve the selected quality and regression criteria, including any
binding veto. Select the sample, stopping condition, effort limit and response to
failure for this task; explain their basis. Wider repetition or a second candidate
requires remaining authorized scope and a useful evidence reason.

Resolve grants for each trial effect, including temporary artifacts, instrumentation,
scratch files, source access and any cleanup. Apply the original methods needed
by the actual artifacts. Use [UPDATE.md](UPDATE.md) for required pre-action
capture/readback, serialization and result history before the first trial effect.
Reference adequate existing plans rather than duplicate them. A failed required
capture blocks that effect; it does not prevent independent read-only analysis.

Execute the selected comparison through the consuming interface. Retain the
baseline and candidate identities, actual inputs/outputs, commands and results,
observed scope, failures and unperformed checks. Inspect quality on concrete
outputs, including relevant regression or held-out cases. A faster incomplete
answer does not satisfy a preserved content requirement. Stop at the selected
bound or a missing prerequisite; do not turn the task into unattended optimization.

**Done:** the bounded trial has attributable results and checked effects, or an
exact partial result and continuation. A command's success is not acceptance.

## Assess and close the learning result

Use [ASSESS.md](ASSESS.md) for every selected criterion and its retain, revise,
gather or reject recommendation. Report gain, regression and uncertainty separately.
Accepted learning can coexist with unknown cost or inconclusive time; state which
claim is supported. Rejection or inconclusive comparison can complete the learning
objective without forcing another candidate or adoption. Scope conclusions to
the observed sample and conditions; controlled fixtures do not prove production
or general quality, cost or time improvement.

Keep decision review, trial application and consumer adoption separate. Retain a
valid prior selection unless adoption is actually requested and granted. Use
[ADOPTION.md](ADOPTION.md) only for that separate application. Report residual
temporary effects and the granted cleanup state; do not silently broaden cleanup.

For an authorized save, retain objective, criteria, versions, actual evidence,
dispositions, remaining prerequisites and next trigger through UPDATE. On fresh
continuation, reopen changing sources and inspect prior effects before any retry.
Update only conclusions affected by new evidence; preserve the original conditions
and valid completed work. If nothing changed, close without another trial or
duplicate history. State the record's actual persistence limit.

**Done:** the requested diagnosis or learning result is usable and recoverable
within its grant. The next evidence step has a concrete trigger and prerequisite;
it is not automatic permission for more trials, deployment or consumer changes.
