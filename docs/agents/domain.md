# Domain docs

## Layout

This repo has a single context: `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

## Exploring the repo

Read the glossary and relevant ADRs before exploring the affected area. If `GLOSSARY-MAP.md` is added later, use it to select the relevant glossary.

If these documents do not exist, proceed silently without proposing to create them upfront. The `domain-modeling` skill creates them when terms or decisions are settled.

## Terms and decisions

Use glossary terms in issues, hypotheses, change proposals, and test names. Before introducing a missing term, check the repo's existing vocabulary; record genuine gaps for `domain-modeling`.

When a proposal contradicts an existing ADR, name that ADR and explain why it should be reconsidered before changing the decision.
