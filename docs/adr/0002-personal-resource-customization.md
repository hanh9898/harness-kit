# Customize core resources through personal overrides

Users can replace or disable supplied core resources through personal customizations while retaining their origin and the core version for comparison during updates. This preserves customization across core updates and makes differences traceable, at the cost of resolving which resource definition applies. Resource management prioritizes flexibility and does not require a draft-to-accepted approval lifecycle.

Removal excludes a resource from the user's effective kit and survives core updates; restoring the core version is explicit. Library changes do not automatically alter harnesses already built from those resources, preserving project control at the cost of reconciling affected harnesses separately.
