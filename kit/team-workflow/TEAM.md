# Team arrangements

Use for responsibilities, collaboration, reviewer selection or independence through setup/evolve. A team-only request can finish with usable roles and context references while retaining the existing sequence. A human with one agent is a valid arrangement. For requested changes to timing, transitions or handoffs, also read [TASKS.md](TASKS.md); that is a separate result.

This is inferred guidance under the accepted capability choices; [SOURCES.md](SOURCES.md) distinguishes accepted policy from supporting research. Reuse existing people, roles and grants. Selection and application use the calling workflow's original-method, authority and record procedure.

## Deliver responsibilities

1. Inspect the current work, owners, selected review criteria and actual source access. Identify who drafts, checks, decides and acts. Reuse adequate roles before proposing another participant. A role may be a named person, an existing responsible group or an available agent route; a proposed role with no available actor remains a readiness gap.
2. For each responsibility, provide its accountable identity, work scope, necessary context and access route, permitted choices/actions, authority reference and escalation owner. Resolve ambiguous ownership for consequential choices before use. A profile or delegation level records a ceiling; it grants no tool or source access.
3. For each review, identify the reviewer, competence/context needed, decision authority and required independence. State what the review establishes. Distinguish editorial quality from accuracy against sources; under the selected document standard, human-only sources require human accuracy review. An agent's self-check is useful but is not independent review. Two role labels on the same actor do not establish independence; neither does a fresh context alone establish a selected requirement for a different reviewer.
4. Inspect the actual references and available reviewer route. Record missing access, unavailable actors and conflicts, with the dependent decision and next action. Preserve useful drafting or editorial work while a human accuracy decision is pending. Do not report review as performed merely because a reviewer is assigned.

**Done:** someone using this arrangement can tell who owns each requested responsibility, what that actor can inspect and decide, and who resolves the remaining gaps. Preserve existing workflow timing unless its change was requested. Report design/application/review evidence separately; a manual arrangement makes no unattended-readiness claim.

## Review interface

Team supplies identity, context, authority and independence. Workflow consumes these references to specify when review starts, its versioned inputs, expected findings or acceptance output, and the correction/handoff path. A workflow-only result can refer to existing roles without onboarding a new team.

For example, a human editor can accept style while the source holder attests interview claims and the release owner authorizes publication. If the source holder also drafted the text, check whether the selected accuracy-review standard permits that relationship; keep any unmet independence requirement visible. Do not invent approval or broaden one review into another.
