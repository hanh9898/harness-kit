# Select applicable standards

Use through setup/evolve for a direct standards request or when selected work
needs criteria. Deliver applicable requirements, conflicts and useful machine
or human checks. Advice can finish without onboarding, factory setup, adoption
or a saved standard. The caller owns the final result, grants and continuation.

## Establish the effective selection

1. Inspect representative work, consuming targets, existing standards, source
   access and prior choices. Retrieve relevant kit summaries/rules through the
   calling entry's CLI, then only determining detail. Reuse adequate material;
   selection is not a reason to replace it or build a checker.
2. For each applicable requirement identify its source/revision, target and
   condition, expected observable result, suitable check, evidence needed and
   failure/unknown handling. Distinguish already binding criteria from proposed
   additions and deliberate non-use with a reason. A machine check is not the
   only valid check; a required human judgment can be the useful result.
3. Resolve conflicting meanings using actual authority and accepted choices.
   For instruction precedence use [instruction/response design](../instruction-response/DESIGN.md).
   Newer files, successful lint or selection by an agent supply no precedence.
   Preserve unresolved meanings, the dependent use and the competent authority's
   decision needed; continue independent criteria and retain valid prior choices.
4. Preserve consumer language/content requirements. Repository English checks
   govern this kit, not consumer artifacts. Use the accepted [writing scope](../instruction-response/WRITING.md)
   where applicable. No blanket task-stage ceiling follows from document work.
   For selected task/flow controls, reuse [workflow guidance](../team-workflow/FLOW.md):
   standards supplies applicable brake/reversibility/limit requirements, while
   workflow owns project values, rationale and handoffs. Factory remains optional.

**Done:** a consumer knows which criteria apply, why, how to check them and which
uses await a conflict decision or missing prerequisite. Existing selections bind
until competent authority changes them with rationale/impact under the procedure
in force before replacement. Selection/edit permission does not itself authorize
consumer adoption, separately governed changes or retrospective self-approval.

## Make checks usable

For document work read [DOCUMENTS.md](DOCUMENTS.md). Account for all six families
against the actual artifact and selected standard; mark a family inapplicable
with a reason rather than running an irrelevant check. Reuse #23 output criteria
for language, form, supported content and uncertainty instead of maintaining a
second output contract. Read required original methods through the calling
entry's [method selection](../../skills/harness/harness-evolve/CHANGE-FLOW.md),
including current writing-for-agents before agent-read authoring. An unavailable
required method blocks that authoring, with the exact access/invocation condition
and continuation; independently useful inspection/advice can still finish.

Keep these meanings independently inspectable, in the existing suitable form:

| Meaning | What establishes it |
| --- | --- |
| Selected | Actual effective requirement, authority, applicable target and source version; a recommendation is still a proposal until validly selected. |
| Performed | Actual check/review action, artifact/source version, actor or tool, conditions and observed evidence. A command suggestion or assigned reviewer is pending work. |
| Satisfied | Evidence meets the selected criterion within its scope; failed, pending, blocked and unknown remain visible. Successful execution alone does not establish satisfaction. |

If the request includes checking, execute available useful checks within its
grant and inspect their outputs. Record tool/version, actual command or review,
result, coverage and remaining evidence. A check that only parsed structure must
not claim render quality or factual accuracy. Reuse [criterion assessment](../../skills/harness/harness-evolve/ASSESS.md)
for evidence interpretation, uncertainty and recommendations; standards owns
which criteria apply, not a competing assessment system or aggregate score.

For human review use the existing [team arrangement](../team-workflow/TEAM.md)
for reviewer identity, competence/context, authority and required independence.
Use [task workflows](../team-workflow/TASKS.md) for timing, versioned inputs,
findings/acceptance output and correction/continuation. Supply criterion/source
references and gaps to those owners. An agent self-check or two role names on
the same actor cannot satisfy required independence. Keep unavailable reviewers
or source access as dependent blockers; do useful editorial work within scope.

**Done:** each selected criterion has a useful check route, actual result or
explicit pending prerequisite, and a bounded next action. Selection can be
complete while accuracy approval and publication remain blocked. Never invent
human review, source facts, waiver or certification to finish the selection.

## Preserve application and continuation

A selection/advice result does not change consumers. For authorized saves or
application use [UPDATE.md](../../skills/harness/harness-evolve/UPDATE.md):
prior authority and timing, pre-action capture/readback, canonical serialization,
actual per-target effects, original-method prerequisites, scratch scope and
preserved history apply from the first write. Preserve original selection and
source revisions when recording a replacement or changed evidence.

Retain the objective, applicable criteria, inspected artifact/source versions,
performed checks, failures/unknowns, review and adoption state, remaining work
and next trigger in the authorized record or advice result. On resume inspect
live state and potentially changed sources before reuse of a result. Keep valid
completed effects; rerun only affected checks and supersede stale conclusions
with linked evidence rather than erasing their historical conditions.

## Source and qualification scope

This inferred procedure implements [spec 15, clauses 15/34/42 and A27/A35](https://github.com/hanh9898/harness-kit/issues/15),
[ticket 24](https://github.com/hanh9898/harness-kit/issues/24) and the accepted
[Q93 recovery](https://github.com/hanh9898/harness-kit/issues/13#issuecomment-6816002303).
These establish product selections, not external certification or host support.
N06 informs focused pointers; E07/E08 inform records and choice history. Existing
consumer standards and source facts remain authoritative for their own work.
Qualification requires actual host/use evidence with provider, revisions, grants
and limits; selected guidance alone proves neither execution nor improvement.
